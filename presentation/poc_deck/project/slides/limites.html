Limites et suites

Limites

  • La validation sert à choisir l'époque et à mesurer : scores un peu optimistes, pour les trois modèles
  • Pas d'augmentation de données : sur‑apprentissage modéré (écart train − validation de +0,06 à +0,08)
  • Points de départ pré‑entraînés différents d'un modèle à l'autre
  • Sans GPU, EoMT perd son avantage de vitesse

Suites proposées

  • Augmentation de données : échelles, recadrages, retournements
  • Servir EoMT par l'API du projet, sur une machine avec GPU
  • Quantification ou distillation pour un usage sur CPU
  • Évaluer sur le jeu de test officiel via le serveur Cityscapes

CityVision · Preuve de concept · 18 / 20

(≈ 45 s) Les limites, honnêtement. La validation sert à la fois à choisir la meilleure époque et à mesurer : les scores sont légèrement optimistes, mais de la même façon pour les trois modèles, donc la comparaison reste juste. Aucun modèle n'a d'augmentation de données, et les transformers sur‑apprennent un peu, avec un écart train − validation de 6 à 8 points. Les points de départ pré‑entraînés diffèrent, c'est inhérent à chaque méthode. Et sans GPU, l'avantage de vitesse d'EoMT disparaît. Suites naturelles : ajouter de l'augmentation, servir EoMT par l'API sur une machine GPU, quantifier le modèle pour le CPU, et évaluer sur le jeu de test officiel.
