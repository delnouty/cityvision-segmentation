Démarche · protocole

Une comparaison équitable

Identique pour les 3 modèles

  • Mêmes images, 9 classes, 512×1024
  • Même échantillonneur pondéré (classes rares)
  • Même budget : 20 époques, lot effectif de 4, arrêt anticipé
  • Même métrique, même code d'évaluation
  • Aucun point de départ n'a vu Cityscapes

Propre à chaque modèle

  • Pré‑entraînement : ImageNet, ADE20K, COCO
  • Recette de son article : perte, optimiseur, calendrier du taux d'apprentissage
  • Lots de 2 + accumulation de gradient pour les transformers (8 Go de GPU)
  • Précision bf16 pour les transformers

Mesures : mIoU et IoU par classe, temps d'inférence, bootstrap apparié sur les 500 images de validation.

CityVision · Preuve de concept · 6 / 20

(≈ 45 s) Pour que la comparaison soit honnête, tout ce qui peut être identique l'est : mêmes images, même résolution, même échantillonneur, même budget d'entraînement, même métrique calculée par le même code. Ce qui diffère est ce qui fait partie de chaque méthode : son pré‑entraînement et la recette de son article. Un détail pratique : mon GPU portable a 8 Go, donc les transformers sont entraînés par lots de 2 avec accumulation de gradient, ce qui donne le même lot effectif de 4 que la baseline. Enfin, pour savoir si un écart est réel, j'utilise un bootstrap apparié sur les images de validation.
