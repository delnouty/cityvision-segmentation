Technical Note

CityVision — Segmentation Serving Solution

Backend prediction API (FastAPI) & presentation frontend (Streamlit) for urban-scene semantic segmentation on Cityscapes.

1. Overview

CityVision trains several CNN segmentation models on the Cityscapes dataset and serves the best one through a REST API. The solution has two deployable components:

  • Backend — a FastAPI service that loads a trained model and, given an input image, returns the predicted segmentation mask.
  • Frontend — a Streamlit application that consumes the API: it lists available image IDs, triggers prediction for a selected ID, and displays the real image, the real (ground-truth) mask, and the predicted mask side by side.

Both layers reuse the same model classes and the same preprocessing (resize to 512×1024 + ImageNet normalization) as the training pipeline, guaranteeing that inference is consistent with how the models were trained.

3.2 API reference

MethodPathDescription
GET/HTML upload page (manual testing).
GET/healthService status + loaded-model info (architecture, checkpoint, val mIoU, device, classes, palette).
GET/docsInteractive Swagger UI.
POST/predictUpload an image → predicted mask as image/png. Query: format=color|overlay|raw, alpha=0..1.
POST/predict/classesUpload an image → JSON of detected classes with pixel coverage.

Output formats. color = colourised mask; overlay = mask blended over the original (controlled by alpha); raw = single-channel PNG of class indices (0–8). Masks are returned at the original image resolution.

3.3 Model selection strategy

At startup the API chooses which model to serve, in priority order:

  1. CITYVISION_CHECKPOINT — explicit path to a .pth file.
  2. CITYVISION_ARCH — architecture name.
  3. Best run recorded in mlflow.db (highest best_val_mIoU with an available checkpoint).
  4. First available checkpoint by quality priority (ResNet50 → ResNet34 → VGG16 → UNet → SegNet).

This keeps the service deployable even when MLflow is not present, while still defaulting to the best validated model when it is. The current best model is ResNet50-UNet (validation mIoU ≈ 0.816).

4. Frontend (Streamlit)

frontend/streamlit_app.py is a presentation UI that consumes the API. It implements:

  • Image ID listing — available IDs for a chosen split (val/test/train), built from the same dataloader used in training (get_cityscapes_pairs).
  • On-demand prediction — a button POSTs the selected image to the API and retrieves the mask.
  • Three-panel comparison — real image · real mask · predicted mask.

Additional aids: API health indicator, overlay toggle with opacity slider, a detected-classes breakdown (with percentages), and a colour legend.

Note on ground truth. The Cityscapes test split has no public ground truth, so its "real mask" panel is all-background. Use the val split for a meaningful real-vs-predicted comparison; the app shows an inline note when ground truth is unavailable.

6. Running the solution

From the project root, in two terminals:

6.1 Backend

uvicorn backend.app:app --port 8000
# UI:    http://localhost:8000/
# Docs:  http://localhost:8000/docs

6.2 Frontend

streamlit run frontend/streamlit_app.py
# opens http://localhost:8501

Serve a specific model (optional): CITYVISION_ARCH=VGG16-UNet uvicorn backend.app:app --port 8000 (PowerShell: $env:CITYVISION_ARCH="VGG16-UNet"; uvicorn backend.app:app --port 8000).
